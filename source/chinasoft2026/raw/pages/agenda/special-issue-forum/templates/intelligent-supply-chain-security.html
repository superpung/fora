智能化软硬件供应链安全分析技术论坛

专刊论坛 S8

一、论坛介绍

随着开放软件生态、开放硬件体系结构以及大模型技术的快速发展，软件、硬件及智能化组件之间的关联日益紧密，供应链对象正由传统的软件组件和硬件模块不断扩展至模型、智能体、AI基础设施及其运行环境等新型对象。不同类型对象之间通过依赖、调用、集成和协同运行等方式形成复杂关联关系，共同构成支撑现代信息系统开发、部署与运行的软硬件供应链体系。供应链已成为影响系统安全性、可靠性和自主可控能力的重要因素，其安全问题受到学术界和工业界的广泛关注。然而，供应链对象类型的持续扩展和依赖关系的不断复杂化，在提升系统能力与开发效率的同时，也带来了新的安全挑战。软件缺陷与漏洞、开源生态投毒、硬件设计缺陷与后门，以及模型、工具服务等新型对象中的安全风险，均可能沿供应链路径传播并影响上层应用系统。与此同时，多类型供应链对象在描述方式、运行机制和依赖关系等方面存在显著差异，风险传播呈现跨层次、跨对象和动态演化等特点，给供应关系识别、风险检测分析以及风险影响评估带来了新的挑战。如何面向软件、硬件与智能化组件构成的复杂供应链体系开展系统化分析，揭示风险传播机理并准确评估其影响，已成为当前供应链安全领域的重要研究课题。

4. 报告人：刘维杰 副教授

题目：TrustRelay:面向大语言模型API供应链的可验证与防篡改中转系统

摘要：随着大语言模型（LLM）应用日益依赖第三方API中转服务，中转服务运营商处于请求与响应的必经路径。因此，中转服务运营商可能读取或篡改请求、替换模型，甚至伪造响应，而客户端通常缺乏能够独立验证此类行为的密码学证据。为弥补这一信任缺口，本文提出TrustRelay，一种面向LLM API的可验证中转系统。该系统将收据签名密钥和加密密钥限制在基于虚拟机的可信执行环境（VM-based TEE）内，并利用远程证明机制，将相应公钥与机密虚拟机的度量状态进行绑定。客户端借助本地Sidecar代理能够验证远程证明证据、加密封装请求、验证响应收据，并保存审计数据包以供离线验证。为支持流式Server-Sent Events（SSE）接口，TrustRelay以请求哈希为种子构造增量SHA-256内容块链。通过这一机制，最终的签名收据能够检测响应数据块的修改、插入、删除、重排序或截断等行为。本文在Intel TDX服务器上实现并评估了基于Rust安全语言的原型系统。测试表明，客户端在规范化处理、签名和加密操作方面的开销较低；数据块哈希链和收据处理仅引入了有限的逐块传输延迟；基于真实DeepSeek服务的实验表明，TrustRelay与直接访问方式的端到端延迟总体上具有可比性。

简介：刘维杰，南开大学副教授，主要从事系统安全方面的研究，研究领域包括应用运行时层、系统软件层、处理器与微体系结构层的安全问题。现任中国计算机学会网络与系统安全专委会、计算机安全专委会的执行委员，星绽开源社区技术指导委员会常务委员。在IEEE S&P、CCS、NDSS、ASPLOS、EuroSys、FAST、FSE、DSN、ESORICS、CHES等国际顶会发表论文多篇，获授权国际专利多项。研究工作发现了Intel、Red Hat、阿里云等产品中的多项安全问题，获得多个CVE/CNVD编号；相关成果在字节、华为、蚂蚁、腾讯等企业的生产系统或研发实践中得到应用。参与研发的Rust安全操作系统项目入选"科创中国"开源创新榜单。主持国家自然科学基金、字节跳动星火计划和CCF—企业联合基金等项目，曾参与国家"863"计划、国家自然科学基金重点项目，以及美国NSF、NIH等科研项目。

5. 报告人：张凯林 本科生

题目：TraceOracle：面向Java软件供应链漏洞候选的路径约束反事实运行时验证方法

摘要：软件成分分析和静态分析工具能够发现潜在漏洞依赖及可疑调用路径，但一个关键问题仍未得到充分解决：检测报告中的路径是否在实际运行环境中产生了对应的安全影响。本文提出TraceOracle，一种面向Java软件供应链漏洞候选的运行时验证框架。在验证过程中，TraceOracle首先固定待验证漏洞路径及预期安全影响，通过执行漏洞版本与修复版本程序，结合触发输入与良性输入，对运行时行为进行观测，并将观测结果与目标路径进行关联。进一步地，框架基于十二项证据约束规则，对漏洞影响进行形式化判定，输出Confirmed、Refuted或Inconclusive三类结果。实验结合受控漏洞归因挑战、组件集成测试以及静态分析与运行时验证对比实验，验证了方法在降低误报、提升漏洞确认可信度方面的有效性。结果表明，TraceOracle能够连接静态分析发现与实际运行影响，为软件供应链漏洞分析提供可审计、可复现的验证机制。

简介：张凯林，北京邮电大学未来学院计算机科学与技术专业本科生，主要研究方向为软件供应链安全、程序分析与智能化代码安全审计。围绕软件供应链漏洞检测与验证问题开展研究，提出TraceOracle：一种面向 Java 软件供应链漏洞候选的路径约束运行时验证框架，通过结合静态分析结果、运行时行为观测以及反事实对照实验，实现对漏洞影响的精确确认与可审计验证。相关研究聚焦于提升软件成分分析、漏洞检测结果可信度及自动化安全分析能力。目前参与北京市自然科学基金"启研"计划《面向大语言模型智能体的多重边图结构记忆构建与检索方法研究》、北京邮电大学未来学院未来学者计划"基于理解推理与迭代验证的代码缺陷深度分析自主智能体研究"等科研项目。曾获国家奖学金，并参与中国移动九天大模型 Harness 项目等实践工作。

6. 报告人：王承杰 博士生

题目：LLM生成代码中的依赖版本建议：发生、质量与后果

摘要：第三方依赖是现代软件不可或缺的组成部分，其版本会影响应用程序能否可复现、可构建以及能否安全维护。随着LLM越来越多地在生成代码的同时生成依赖信息，它们能够影响开发者所采用的版本选择。然而，LLM会给出什么样的版本建议、这些建议有多可靠和多及时，以及采用这些建议后会发生什么，目前仍不清楚。我们从Stack Overflow的1,000个真实世界Python开发任务构建了 PinTrace 数据集，在10个商业和开放权重LLM上，研究模型生成的依赖版本建议的发生、质量和后果。我们比较了清单请求（MR）和版本标注请求（VA）：前者要求提供依赖文件，后者要求提供具体版本；并追踪由此产生的环境在解析、安装和验证过程中的情况。在完整PinTrace中每种条件下10,000个响应里，精确约束和范围约束分别出现在17.75%和26.15%的MR响应中，而精确建议出现在81.19%的VA响应中。我们在不含目标依赖版本信息的干净任务子集上评估建议质量。在VA下有效的精确推荐，在实验截止点时，其模型层面的中位发布年龄为22-43个月。安全筛查发现，在该子集中，所有MR响应中有9.46%、所有VA响应中有39.49%的有效精确建议与已知漏洞相关联，而在所有MR响应中，范围解析后的建议中有7.57%存在这种关联。在完整PinTrace中，50.44%的MR响应和34.32%的VA响应生成的环境完成了安装和静态验证。我们进一步使用813个BigCodeBench任务，以可执行测试扩展环境验证。在每种条件下8,130个生成响应中，执行测试在MR下的端到端通过率为42.47%，在VA下为16.42%。这些发现支持在采用模型生成的依赖建议之前，检查发布时效性、筛查已知漏洞，并验证工程兼容性。

简介：王承杰，中国科学院软件研究所博士生，导师赵琛研究员，主要研究方向为软件供应链安全、大模型应用安全，相关成果发表在 TOSEM 等软件工程领域顶级期刊上。曾获得硬件安全领域规模最大的RISC-V 硬件漏洞挖掘竞赛 HACK@DATE2025 与 HACK@DAC2026 两届全球冠军。

7. 报告人：张一筝 博士生

题目：基于伪代码证据的轻量级、模型无关的二进制代码相似性检测重排序方法

摘要：二进制代码相似性检测（Binary Code Similarity Detection, BCSD）广泛应用于漏洞搜索、恶意软件分析以及软件组成分析等。然而，程序架构、编译器以及优化方式的变化会改变底层表示形式，即使真实匹配样本存在于Top-K候选集合中，也可能导致其排名较低。本文提出了一种轻量级、模型无关的重排序方法，该方法利用从反编译伪代码中提取的证据链进行优化。该方法通过语义锚点检测、上下文绑定、确定性归一化以及指纹生成等技术，将字符串、常量、函数调用、局部变量值流和表达式组织成八类证据链。对于每一个查询代码与候选代码对，该方法统计它们之间共享的指纹数量，并在不改变候选集合的情况下稳定地重新排序基线模型产生的Top-K列表。该方法无需额外训练、分数校准或神经网络推理。我们在两个独立采样的基于BinKit的评估数据集上进行了实验，涵盖三种实验设置和四种异构基线检索器。实验结果显示，平均Reciprocal Rank（MRR）分别提升了27.6个百分点和20.8个百分点，而Recall@1分别提升了29.8个百分点和18.8个百分点。证据统计、消融实验以及字符串稀疏实验表明，该方法除了字符串匹配之外，还能够提供互补的有效信息。对于每个查询样本的重排序过程，在K=10,000时，单个CPU上无需GPU或额外模型推理，仅需约25毫秒。排序变化始终可以追溯到具体的伪代码证据。

简介：张一筝，信息工程大学网络空间安全专业在读博士生，师从刘胜利教授，主要研究领域为二进制相似性检测技术，聚焦于跨平台的二进制相似性检测技术，以及基于二进制相似性检测的软件安全分析技术。

8. 报告人：陈奕铭 硕士生

题目：Kimulator: 面向硬件工具链的基于语义的仿真与失效分析

摘要：复用的硬件组件及对其进行转换的工具，需要在集成边界进行行为一致性检查。当检查失败时，必须将观察到的输出差异与产生该差异的计算过程和状态更新关联起来。本文基于现有的 CIRCT（Circuit IR Compilers and Tools）中间表示可执行语义 K-CIRCT，在 Kimulator 中提出了一套仿真与故障分析工作流程。其核心贡献在于，利用保存的语义执行状态重建数据依赖、控制依赖和历史状态依赖，从而将异常信号的观测结果与其产生原因关联起来。本文设计了一种基于事件的执行接口，将输入信号、时钟变化、保留的配置以及波形采样关联起来。Error-trace（错误轨迹）分析器利用这些记录，识别不同事件中的操作数取值、控制信号的选择情况以及相关寄存器的状态更新。通过一个帧长度相关的案例，展示了该分析方法如何揭示从上一帧保留下来的计数值，并通过后续设计的定向测试进一步验证这一解释。本文通过三组实验评估该方法的执行基础：第一组实验覆盖 42 个具名操作条目；第二组实验记录三个处理器设计的执行情况及运行开销；第三组实验涉及来自九个公开源代码案例的十种已知缺陷变体。在固定配置和输入轨迹的条件下，参考版本与缺陷版本生成的共 20 组波形均与 Verilator 的结果一致，同时，独立的预期输出检查器成功复现了全部十种已知故障。实验结果表明，可执行语义能够为硬件行为检查与故障调查提供具体且可行的技术支持。 与此同时，执行开销和当前支持的硬件构造范围，也限定了该方法现阶段更适用于有针对性的硬件供应链分析场景。

简介：陈奕铭，浙江大学计算机科学与技术学院在读硕士生，师从赵永望教授，主要研究领域为形式化验证。

9. 报告人：宋文纳 特任副研究员

题目：基于Android密钥库的裁剪图像认证与安全恢复

摘要：图像裁剪是移动设备上的一项关键图像编辑功能，广泛应用于社交分享、文档提交等场景。该功能允许用户从原始图像中提取特定的感兴趣区域，而实际使用中往往需要对不同区域进行多次裁剪。然而，传统裁剪流程通常依赖原始图像的持续可用性来支持后续重新裁剪；一旦仅剩裁剪后的图像，用户便无法再次选择已被移除的区域。另一方面，如果在裁剪图像中保留足以恢复原始图像的信息，而这些可恢复内容未得到充分保护，则可能引发隐私泄露风险（例如CVE-2023-21036），使未经授权的第三方能够恢复用户原本希望移除的内容。为解决这一问题，本文提出了一种基于 Android Keystore的认证增强型图像裁剪与恢复方法。该方法将经过密码学保护的恢复数据嵌入可正常查看的裁剪图像中，同时利用Android Keystore保护恢复密钥。只有当数据认证和设备验证均通过时，系统才会接受恢复数据并恢复原始图像。本文在20台不同的实体移动设备上对该方法进行了评估，覆盖400组有序设备配对配置，其中包括20组同设备配对和380组跨设备配对。所有同设备恢复尝试均成功恢复了原始图像文件，而所有跨设备恢复尝试均被拒绝。此外，该方法检测出了所有测试中的篡改尝试及恢复数据不完整情况，并拒绝了相应的恢复操作，且全部鲁棒性测试用例均通过。综上，该方法能够在无需单独存储源图像文件的情况下，实现原始图像文件的安全恢复。

简介：宋文纳，华中师范大学计算机学院特任副研究员，主要从事软件安全、移动安全及人工智能应用安全研究，重点关注软件与系统的安全威胁分析和漏洞挖掘。相关研究成果发表于 ACM CCS、ICSE 等国际学术会议及《软件学报》等权威期刊。发现的多项软件安全漏洞已获得Netflix、亚马逊、腾讯、爱奇艺、阿里巴巴、金山和小米等厂商或其安全应急响应中心的确认，部分漏洞已获分配 CVE 编号。
