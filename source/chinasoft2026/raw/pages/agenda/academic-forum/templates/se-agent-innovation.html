软件工程智能体创新论坛

学术论坛 R2

一、论坛介绍

随着大语言模型与智能体技术的持续发展，软件研发正从AI辅助编程迈向智能体驱动的全流程协作新阶段。“软件工程智能体创新论坛”旨在汇聚学术界与产业界专家，围绕AI原生软件工程的关键技术、研发范式与产业实践展开深入探讨。

本次论坛聚焦Spec驱动开发、多智能体协同、长程任务执行、智能体训练与自进化、研发技能与知识体系构建，以及代码理解、测试验证与可信质量保障等方向，交流最新研究成果与工程经验。结合企业级智能研发平台建设、复杂软件开发及跨平台代码迁移等真实场景，探讨软件智能体从能力提升到工程落地的关键挑战，推动智能体技术在软件研发全场景中的应用，促进学术研究与产业创新的协同发展。

四、论坛报告嘉宾简介

1. 报告人：潘瑞琪 华为2012实验室软件工程实验室主任

题目：是驾驭先进生产力的利器还是束缚生产力围栏

摘要：各类围绕应用大模型进行开发而产生的智能体平台如雨后春笋应运而生，一方面这些平台让大家更容易，更大范围的使用好智能化，另一方面，又有各类现实风险让我们必须建立好护栏控制使用，那么作为一个智能化开发平台应该如何平衡呢。

简介：潘瑞琪，现任华为2012实验室软件工程应用技术实验室主任，长期致力于企业级软件工程方法的研究与规模化落地，拥有超大规模软件开发协作的一线实战经验。他深谙大规模、长生命周期复杂软件工程面临的核心挑战，对智能化浪潮下软件工程的重塑有着深刻洞见。近年来，他重点聚焦AI辅助研发及研发范式升级，在SPEC驱动开发、代码Agent质量保障与评测、领域知识工程等方向取得了深入的研究成果和扎实的落地实践。

2. 报告人：谢吉宝 Qoder 技术负责人

题目：Qoder：不止编程，无限创造

摘要：过去，开发者坐在 IDE 前逐行编写、补全、编译和调试代码；今天，越来越多的人只需说清目标，剩下的拆解与执行都可以交给智能体，人的核心工作变成了计划、委派和验收。Qoder 的使用数据印证了这一转变：三成以上用户不是专业开发者，一半以上任务已不是传统编程，八成以上编程任务交由智能体执行。代码正在从交付物变成数字世界的通用能力，Qoder 因此定位为"Agentic Coding Platform for Everyone"。本次分享将展示：人如何与多个 Agent 围绕同一个任务共同讨论、分工协作，不必再在聊天群和多个终端之间来回搬运上下文；如何通过语音、手机等随身入口随时委派和验收，让任务在云端持续运行、不再依赖人全程在线。Qoder 的起点是编程，但目标从来不只是多写几行代码，而是让每个人都能借助 AI，把想法真正变成结果。

简介：谢吉宝（花名唐三），阿里巴巴资深技术专家，Qoder 技术负责人，统筹 Qoder 全系列产品的技术体系与研发。深耕大型分布式系统十余年，曾主导中间件核心组件、异地多活容灾及双 11 全链路稳定性保障。近年他聚焦 AI 编程与智能体（Agent）方向：一条主线持续突破 Agent 在长程任务规划与自主执行、上下文工程和工具调用等方面的能力边界；另一条主线构建以能力评测、安全沙箱、权限与审计为核心的可信体系，让组织敢于将复杂任务真正交给 Agent。两条主线最终收敛为统一的 Agent 内核，支撑终端、桌面与云端多种产品形态。他认为，AI 编程的下一步，不是让用户多写几行代码，而是让编程成为每个人都能调用的通用能力。

3. 报告人：王龙 微信专家研究员

题目：AgentSwarm 在软件工程中的应用

摘要：大模型驱动的智能体（Agent）正在从"单点辅助"走向"群体协作"。本报告围绕两个方向展开：（一）AgentSwarm 在软件工程中的应用。介绍 AgentSwarm 多智能体协作体系在微信支付软件工程场景中的落地实践，包括任务分解、组网、智能体间的通信与冲突仲裁机制，以及在真实研发流水线中的典型应用（软件设计，数字孪生）。（二）基于 AgentSwarm的复杂代码仓库逆向数字孪生。面对遗留系统与超大代码仓库中"文档缺失、知识散落、依赖隐晦"的现实困境，介绍如何以增强型UML为载体，通过多智能体协同对代码仓库进行系统性逆向解析，将隐性的架构决策、业务语义与依赖关系抽取为结构化、可演进的知识资产，并做双向锚定，实现从"代码"到"知识"的逆向工程与工程化沉淀，为系统的可维护性、可迁移性与智能研发提供基础设施。

简介：王龙，腾讯微信支付瓦特实验室研究负责人，专家研究员，长期从事AI4SE的研究及其在金融级软件工程场景中的落地。

4. 报告人：魏长征 蚂蚁集团数字科技技术总监

题目：从「可用」到「可交付」：AiWork 的 Agent Harness 工程与企业级研发实践

摘要：大模型智能体正从"辅助补全"走向"在后台独立完成真实仓库与业务任务"，软件工程的核心问题也随之从"能不能生成代码"转向"需求是否对齐、测试是否充分、证据是否可复查、长任务与多智能体并行是否可控、交付能否被验收"。本报告以蚂蚁数科 AiWork通用智能体与工程实践为线索，介绍如何把需求澄清、契约先行、测试、评审、CI/CD、回滚与复盘等经典软件工程经验，重构为智能体可执行、团队可验收的运行时能力。报告将拆解 AiWork 的核心技术：面向长任务的上下文工程（分层组装、按需加载、分级压缩与断点续作）、以子智能体委派为核心的规划编排，以及"运行状态 / 结果契约 / 任务验收"三层分离的交付验证与整棵委派树的开销核算。在此基础上，报告进一步落到 AiWork 的企业级能力：以统一内核为底座，按研发、办公与业务场景组合 Code / Work / Space，用模型路由、审批、沙箱与审计覆盖智能体全生命周期，帮助企业把 AI 研发从"可用"做成可控、可运营、可规模化落地的生产级能力。

简介：魏长征，蚂蚁数科技术总监、资深技术专家，上海市数字技术领域高级工程师，在蚂蚁数科工作超 7 年，长期从事智能体工程、区块链、隐私计算与软硬件结合等方向的研发。具备长期的软件工程研发经验，领导团队完成多个商业化平台的建设与落地，并推动团队向 AGI 研发范式转型。曾发表 10 余篇 CCF A 类国际会议和期刊论文，拥有国内外授权专利 50 余项，并主导或参与多项国内外技术标准制定。

5. 报告人：张克驰 腾讯混元大模型Agent Harness负责人

题目：长时运行智能体建设方法与挑战

摘要：近年来，大语言模型在代码生成、软件测试、程序修复、知识检索和复杂任务求解等领域快速发展，推动智能软件工具从一次性的问答辅助和代码补全，逐步走向能够持续规划、执行、验证和迭代的智能体（Agent）系统。与传统代码生成技术相比，长时运行 Agent 不再只关注单次输出的正确性，而是需要在更长时间尺度上理解目标、拆解任务，并根据反馈不断修正执行路径，从而完成复杂工程任务。与此同时，长时运行 Agent 的工程化落地也带来了新的挑战：受限于模型上下文，Agent 在长任务中容易出现目标漂移等问题；由于缺乏可靠的外部校验机制，也容易出现过早宣布完成或隐蔽错误等现象。ProgramBench、SWE-Marathon 等长时程基准的实践也进一步表明，当前智能体在长时间跨度的复杂软件任务上仍远未可靠。本报告将围绕长时运行 Agent 的方法展开，探讨流程编排、任务分解等核心方法，并分析仍需解决的关键挑战。

简介：张克驰，目前在腾讯混元大模型团队负责Agent Harness算法研究，核心参与Hy3、Hy4模型训练和Agent协同设计。博士毕业于北京大学计算机学院，导师为金芝教授和李戈教授，本科毕业于北京大学信息科学技术学院，研究方向为代码智能体、代码大模型与智能化软件工程。他曾以第一作者在自然语言处理、软件工程等领域的国际会议上发表多篇论文。其代表工作 CodeAgent 发表于 ACL 2024，是较早系统性研究代码智能体的工作之一。一作论文先后获得 2023 年 ACM 杰出论文奖（ACM SIGSOFT Distinguished Paper Award in ICPC）和 2026 年 ACM 杰出论文奖（ACM SIGSOFT Distinguished Paper Award in ICSE）。

6. 报告人：石琳 北京航空航天大学软件学院教授，院长助理

题目：暗知识驱动的可信代码智能体构建

摘要：软件开发过程中包含大量暗知识。所谓暗知识，是无法仅通过阅读最终代码获取，来源于开发行为、排障调试、设计取舍、失败教训等过程的经验性知识，涵盖设计动机、隐式契约、失败模式、隐式依赖、排障方案、开发者画像等多类信息。当前业界主流的代码 RAG、分层记忆智能体大多只利用显性、半显性结构化信息，对暗知识挖掘复用不足，这也是智能体产生幻觉、不合规、输出不可落地的重要根源。本次报告介绍暗知识的获取、结构化与复用技术路径，分享 VirtualME、DevSkill、DevBrain、CREDIT 评估体系等系列研究成果：通过 IDE 采集开发者行为轨迹，构建开发者画像实现个性化研发问答；从真实开发轨迹中提取可迁移的任务求解 Skill，提升复杂开发任务的规划与执行正确率；进一步解构任务技能，基于过程知识图谱实现任务方案的动态组装，突破简单步骤模仿，向最优解搜索跃迁；同时提出人机协作可信度量化评估框架 CREDIT，实现 AI 辅助开发过程的可度量、可问责。为构建真正可用、可控、可追溯的生产级可信代码智能体提供新思路与实践参考。

简介：石琳，北京航空航天大学软件学院教授，院长助理，空天软件智能测试北京重点实验室副主任。研究方向为智能软件工程，包括仓库级代码智能、智能需求工程、开源软件、可信AI等。在软件工程、人工智能领域的高水平国际会议ICSE，FSE，ASE等发表论文70余篇，获CCF软件工程青年科技奖，三次获杰出论文奖。主持GF基金重点项目、多项国家自然科学基金项目、企业合作项目20余项。研究成果落地华为、阿里、中国航空工业集团、招商银行等知名企业。

7. 报告人：冯涛 清华大学助理教授

题目：经验、记忆与技能：从持续学习到自进化Agent

摘要：随着大语言模型和智能体的发展，能力不再局限于模型参数，还可以存储在外部记忆、可复用技能和交互规则中，持续学习也因此从模型训练问题扩展为整个智能体系统的能力演化问题。本次报告介绍持续学习在模型生命周期、能力存储载体和更新机制上的最新发展，探讨从参数更新到记忆积累、技能进化与推理时学习的技术路径，并进一步讨论主动遗忘、自主反馈闭环和长程任务评估等关键挑战，展望能够从自身经验中持续学习、积累并迁移能力的下一代 Agent。

简介：冯涛，清华大学助理教授，曾在清华大学计算机系担任博后/助理研究员、于阿里巴巴-达摩院从事研究工作；研究方向为人工智能、多模态、自进化智能体等。主持及参与国家自然科学基金重大项目、中央引导地方专项、面上项目等，在CVPR、ICML、NeurIPS、ICLR、IJCV等人工智能会议及期刊发表论文40余篇，多次入选会议亮点论文，GitHub累计星标5千余次；参与多项国际、国家人工智能标准编制工作，涵盖基础模型、智能体、具身智能等。

8. 报告人：董益宏 上海交通大学计算机学院助理教授

题目：面向长程软件开发任务的大模型强化学习方法

摘要：大模型驱动的软件智能体正从单次代码生成走向涉及多轮决策与环境交互的长程软件开发。然而，长程任务探索成本高且成功轨迹稀缺，使强化学习面临训练开销过大和有效学习信号不足的挑战。本报告围绕"如何拓展模型探索能力，并高效地从长程交互中学习"这一问题，介绍相关研究进展。首先，结合混合策略优化方法 RL-PLUS，讨论强化学习中的能力边界收缩现象，以及融合外部示例与自主探索、拓展模型推理能力的方法。随后，重点介绍面向长程软件开发的强化学习框架 SPROUT：通过同步保存和恢复智能体上下文与执行环境，复用失败尝试中已有的有效进展；利用验证反馈驱动失败分析、回溯位置选择与分支探索，获得更多可用于学习的成功轨迹；进一步通过策略优化，将纠错探索经验转化为模型自身的任务执行能力。报告将结合代码库问题修复与终端交互任务的实验，展示 SPROUT 在任务解决率与训练效率方面的改进，并讨论面向复杂软件开发的软件智能体训练方法与未来研究方向。

简介：董益宏，上海交通大学计算机学院PI（长聘轨助理教授，博导），研究聚焦于智能化软件工程、大语言模型以及多智能体协同，发表CCF-A类学术论文40余篇，其中一作论文引用2200余次，且多项学术成果转化为实际应用落地，提出最早的多智能体协同软件开发框架Self-collaboration，曾获通义阿里星、字节 TikTok、京东 TGT、腾讯青云、美团北斗等顶尖人才计划，以及CCF软工专委博士学位论文激励计划、北京大学优秀博士学位论文、北京大学计算机学院"学术十杰"、中国科协博士青托计划、CCF青年开源专项基金种子计划、ACL Best Paper Candidate、ACL SAC Highlight Award等10余项荣誉奖项。

9. 报告人：曹嘉伦 帝国理工计算机系助理教授

题目：真实世界中的 Agentic Skills：建模、检索、评估与演进

14. 报告人：卜磊 南京大学教授

题目：智能体驱动的形式化程序规约生成与代码验证

摘要：代码验证是保障软件可靠性的重要技术。对于复杂软件系统，验证往往需要借助循环不变式、函数契约等辅助规约，为程序行为提供精确的语义描述，支撑验证任务的分解与组合。大语言模型为辅助规约的自动构造与程序验证任务的自动化提供了新机遇，但现有方法在过程间规约依赖处理以及验证失败的根因定位与针对性修复等方面仍存在不足。本报告介绍一种智能体驱动的形式化程序规约生成与代码验证方法。该方法将智能体的决策能力与程序验证任务相结合，通过规划、生成、修复与评估等智能体的协同工作，迭代构造和完善辅助规约，并利用检索增强生成、验证反馈与质量评估机制，提升规约对程序验证的支撑能力。基于多个实际复杂项目的实验结果表明，通过生成可验证的辅助规约，该方法能够有效支撑复杂程序的安全性质验证，为复杂软件的自动化验证提供了新的技术途径。

简介：卜磊，教授，博士生导师，现任南京大学软件学院副院长，兼任 CCF 系统软件专委副主任（执行）；主要研究领域涉及可信软件、软件工程、形式化方法等方面，部分创新性工作发表在相关领域重要期刊与会议如《中国科学》、TCAD、TC、TOSEM、TDSC、CAV、RTSS、ICSE、DAC等上；入选高校计算机专业优秀教师奖励计划、CCF-IEEE CS青年科学家奖、中创软件人才奖、NASAC青年软件创新奖等奖项，主持基金委青A、重点、国际合作等项目多项。
