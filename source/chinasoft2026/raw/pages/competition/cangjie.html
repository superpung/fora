仓颉杯智能编程大赛

为推动高校软件工程、计算机科学与技术、人工智能及相关专业实践教学改革，加强智能软件、智能体工程及编程语言相关领域创新型、工程型人才培养，促进高校、科研机构和企业之间的交流合作，现举办2026“仓颉杯”智能编程大赛。

大赛坚持“开放创新、重视代码、强化工程实践”的办赛理念，鼓励高校学生围绕真实应用场景开展需求分析、软件设计、程序开发、人工智能技术应用、测试验证和部署运行，通过竞赛提升学生的技术创新、工程实践、系统设计和团队协作能力。

一、竞赛主题

本届大赛主题为：智能软件与智能体工程实践

大赛采用开放命题方式，不限定具体应用领域。参赛队可围绕教育、科研、工业、医疗、金融、办公、内容创作、软件开发、公共服务及其他实际场景自主选题。

参赛作品应以可运行的软件系统为主要成果，并结合大模型、智能体、机器学习、自然语言处理、计算机视觉或其他智能技术解决实际问题。

作品中的智能技术应承担实际功能，并与具体应用场景、业务流程或软件工程过程形成实质性结合。仅调用通用模型实现简单问答、仅在现有软件中增加独立AI聊天功能，或者仅更换模型、提示词、界面和应用场景而未形成实质性功能设计和工程实现的作品，不属于大赛重点鼓励的方向。

二、赛道设置

（一）创新原型赛道

鼓励参赛团队探索智能技术在新场景、新需求中的概念验证、交互创新和功能突破，重点考察作品的创新性、核心功能、智能技术应用和技术可行性。

创新原型赛道作品可以适当简化外围功能，但应具有清晰的核心功能主线，并形成至少一个可实际运行和验证的功能闭环。

（二）综合系统赛道

面向具有较完整业务逻辑和工程体系的软件系统，重点考察参赛团队在复杂智能软件系统中的架构设计能力、工程实现能力和全生命周期开发规范。

综合系统赛道作品应具有较完整的用户角色、业务场景、功能模块和数据流程，主要功能之间能够协同运行，并具备必要的异常处理、安全保障和运行维护能力。

赛道分别制定评审标准并独立评分。每支参赛队只能选择一个赛道参赛。

大赛原则上不限制编程语言、开发框架、基础模型和技术路线，鼓励参赛队使用仓颉编程语言及相关技术生态完成核心模块或创新功能。

四、报名参赛

（一）参赛对象

全国普通高等院校全日制在籍本科生、硕士研究生和博士研究生均可报名参赛。

（二）组队要求

  1. 大赛以参赛队为基本单位报名，每支参赛队由1—6名学生组成，其中设队长1名。
  2. 每名学生只能参加1支参赛队。
  3. 每支参赛队只能选择1个赛道，并提交1件作品，不得重复提交相同或高度相似的作品。
  4. 每支参赛队可配备0—2名指导教师。指导教师可以对项目方向、技术路线和项目管理提供指导，但不得替代学生完成核心代码、系统架构、主要文档或者答辩。
  5. 参赛学生应来自同一所高校，允许跨学院、跨专业、跨年级组队，不允许跨校组队。
  6. 作品提交截止后，团队成员、指导教师和参赛赛道原则上不得变更。确因学籍状态变化、重大健康原因或明显信息填报错误等特殊情况确需调整的，应由队长提交书面申请并说明理由及佐证材料，经组委会审核批准后方可变更。

参赛队应通过大赛官方平台完成报名和作品提交。

五、作品要求及提交材料

参赛作品必须具有实际可运行的软件实体，做到可运行、可测试、可验证。

大赛不接受纯概念设计、静态原型、界面效果图、演示幻灯片或者无实质功能代码的作品。

1. 创新原型赛道提交材料

参赛团队须提交以下材料：

  1. 项目说明文档，包括项目背景、应用场景、核心功能、创新点和技术方案；
  2. 源代码仓库地址或完整源代码压缩包；
  3. 可运行程序包、部署说明或在线体验地址；
  4. 作品演示视频，重点展示核心功能和真实运行效果；
  5. 开源组件、第三方模型、外部 API 或数据集使用说明。

2. 综合系统赛道提交材料

参赛团队须提交以下材料：

  1. 项目说明文档，包括项目背景、需求分析、功能模块、创新点和应用价值；
  2. 系统设计文档，包括总体架构、模块划分、接口设计、数据流转和关键技术实现；
  3. 源代码仓库地址，须包含版本控制历史；
  4. 可运行程序包、部署文档、环境配置说明；
  5. 作品演示视频，须展示系统主要业务流程和核心智能功能；
  6. 开源组件、第三方模型、外部 API 或数据集使用说明。

所有提交材料应真实、完整并相互一致，能够支持评审专家理解、运行和验证作品。

作品使用外部模型、第三方平台、云服务或者在线接口的，应如实说明依赖关系和使用方式，并保证评审期间能够正常使用。

因第三方服务临时故障、区域性网络异常等非参赛队可控原因导致评审时无法访问的，参赛队应及时向组委会说明并提供相应证明，由组委会结合故障影响和已提交材料确定后续核验方式。

因账号失效、欠费、额度不足、密钥配置错误、部署维护不当等参赛队自身原因导致作品无法运行的，按照作品实际运行情况进行评审。

六、竞赛评审

（一）初评

初评采用作品材料评审、代码核验和运行测试相结合的方式。

每件作品原则上由不少于5名专家独立评分，根据对应赛道评审标准，对作品的创新性、技术水平、实际运行效果、工程质量和团队贡献等进行综合评价。

初评结束后，根据作品评分和实际参赛情况确定决赛入围名单。决赛入围比例原则上为有效参赛作品总数的20%—30%，组委会可根据作品数量和质量适当调整。

（二）决赛

决赛采用项目陈述、实机演示、随机功能测试和专家答辩相结合的方式。

每支参赛队原则上安排：

  • 项目陈述：5分钟；
  • 实机演示：8—10分钟；
  • 专家问答：8—10分钟。

评审专家可根据作品实际情况进行代码定位、架构说明、异常场景测试或者非预设输入测试。

决赛重点考察作品的真实运行效果、技术实现、工程质量，以及参赛队员对作品核心代码、系统设计和技术方案的实际理解。

七、评分标准

（一）创新原型赛道

采用百分制：

评分项目 分值
创新性与应用价值 30分
核心功能与运行效果 25分
智能技术应用深度 20分
技术实现与可复现性 15分
材料与答辩表现 10分

（二）综合系统赛道

采用百分制：

评分项目 分值
系统完整性与运行稳定性 25分
架构设计与工程质量 25分
智能技术应用深度 20分
创新性与应用价值 15分
测试、部署、材料与答辩 15分

每件作品原则上由不少于5名专家独立评分。在有效评分不少于5份的情况下，去掉一个最高分和一个最低分后计算平均分。

初评成绩原则上仅用于确定决赛入围名单，不计入决赛最终成绩。

使用仓颉编程语言及相关技术开发的项目，视使用、理解深度等情况，可获得至多不超过5分的额外加分；团队总分不得超过100分。

八、人工智能工具使用及作品真实性

大赛允许参赛队合理使用大模型、智能编程助手等人工智能工具辅助作品开发。

参赛队应按照要求说明所使用的主要人工智能工具及使用范围，并能够清晰说明作品的系统设计、核心代码和关键技术。

严禁使用人工智能工具伪造运行效果、测试数据、代码历史或者其他参赛材料。

参赛作品应由报名学生团队主导设计和开发，核心创意、主要功能和核心代码应体现参赛学生的实质性贡献。

组委会和评审专家有权通过源代码、版本提交记录、成员问答、功能复现、指定代码说明、运行测试和代码相似度检测等方式核验作品真实性和团队贡献。

存在抄袭、代做、冒用他人成果、伪造代码记录、隐瞒既有成果等违规行为的，将根据有关规定取消相关成绩、晋级资格、参赛资格或者获奖资格。

十、知识产权与学术诚信

除另有约定外，参赛作品的知识产权归参赛队及相关权利人所有。

参赛作品涉及学校、实验室、企业或者其他单位已有成果的，应取得必要授权，并在提交材料中如实说明有关权利归属。

作品使用第三方代码、开源软件、模型、数据、图片、音视频、接口等资源的，应按照相关许可证、授权协议或者平台规则合法使用并注明来源。

已发表论文、已有科研项目、课程项目、开源项目或者曾参加其他竞赛的成果可以作为参赛基础，但应如实披露，并说明本次参赛新增的功能、代码和工程工作。
